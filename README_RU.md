**Языки:** [English](README.md) · **Русский**

Локальный зашифрованный менеджер секретов для командной строки. Пароли, API-ключи и личные
заметки живут в одном бинарном файле, зашифрованном AES-256-GCM с ключом из Argon2id.
Криптопримитивы взяты из аудированных библиотек (`cryptography`, `argon2-cffi`); всё вокруг них —
бинарный формат, атомарная запись с file lock, детекция rollback, CLI — написано вручную. Без
облака, без синхронизации, без сетевого стека где бы то ни было в коде.

> **Что это такое (и чем не является).** Это **локальный файл**, а не сервис: нет браузерной
> интеграции, автозаполнения, team-sharing и синхронизации между устройствами — всё это явно вне
> скоупа. Программа также не защищает от кейлоггеров, malware и того, кто уже контролирует вашу
> работающую машину; см. [Модель безопасности и ограничения](#модель-безопасности-и-ограничения).

## Быстрый старт

Если хочется просто посмотреть, как это работает — весь цикл от начала до конца:

```bash
# 1. установка
uv sync          # или: pip install -e .

# 2. создание vault'а (запросит мастер-пароль)
vault init

# 3. сохранить секрет
vault add github --username octocat     # секрет вводится скрыто

# 4. получить — копирует в буфер, автоочистка через ~20 секунд
vault get github

# или вывести на экран вместо копирования
vault get github --print
```

Всё работает локально на одной машине — без аккаунтов, API-ключей и демонов, остающихся после
завершения команды.

## Ключевые особенности

- **Только аудированные примитивы.** AES-256-GCM — из pyca `cryptography`; Argon2id — из
  референсных биндингов `argon2-cffi`. Криптография руками не пишется: самописная криптография —
  так рождаются тихие уязвимости, и ни одна из них не проявляется в юнит-тестах.
- **Запись, безопасная при сбоях.** Каждое сохранение идёт tmp-файл → `fsync` → `os.replace`.
  Выключение света в середине записи оставляет либо старый vault, либо новый — никогда
  полусайлом.
- **Безопасность между процессами.** Advisory file lock покрывает весь цикл
  чтение-расшифровка-мутация-шифрование-запись, включая sidecar с ревизией; при занятом lock'е —
  структурная ошибка `VaultBusyError` по таймауту, а не зависший процесс.
- **Детекция rollback.** Каждая запись увеличивает монотонный счётчик, хранящийся и в заголовке,
  и в sidecar-файле; если vault подменили старой копией, вы получите явное предупреждение.
  Детекция, не предотвращение — и задокументировано именно так.
- **Ошибки без oracle.** Неверный пароль и битый шифротекст дают одинаковый текст и одинаковый
  exit code; структурные повреждения — одно общее сообщение. Ошибки ничего не рассказывают
  скриптам атакующего.
- **Честный аварийный выход в plaintext.** `--unsafe-plaintext-json` существует для миграции,
  но на пайпах/CI требует двух независимых факторов подтверждения (`--yes-i-understand` И
  литеральный `y` на stdin).
- **Типизация насквозь.** Схемы Pydantic v2 везде, `mypy --strict` обязателен и чист.

## Формат хранилища

Один бинарный файл (по умолчанию `~/.secure_vault/vault.enc`). Поля заголовка до nonce связаны
с шифротекстом как AEAD additional data — подмена любого из них ломает расшифровку:

| Offset | Размер | Поле | Примечание |
|---|---|---|---|
| 0 | 4 | magic `b"SSV\x00"` | экспорт использует `b"SSVE"` |
| 4 | 1 | версия формата | = 1 |
| 5 | 1 | kdf_type | `0x01` = Argon2id, протокольная константа |
| 6 | 16 | salt | генерируется один раз при `init` |
| 22 | 1 | argon2_time_cost | диапазон валидируется при чтении |
| 23 | 4 | argon2_memory_cost_kib | big-endian |
| 27 | 1 | argon2_parallelism | валидируемый диапазон |
| 28 | 1 | argon2_hash_len | = 32 → 256-битный ключ AES |
| 29 | 8 | revision_counter | big-endian, монотонный |
| 37 | 12 | AES-GCM nonce | свежая случайность на каждую запись |
| 49 | N | ciphertext ‖ GCM tag | tag = 16 байт |

Расшифрованный payload — JSON-сериализация `VaultMetadata`: записи содержат `id` (UUID), `title`,
`username`, `secret`, `notes`, `tags` и временные метки. Побайтовые детали — в
[ARCHITECTURE_ru.md](ARCHITECTURE_ru.md) §5.

## Структура проекта

```text
secure-secrets-vault/
├── src/secure_secrets_vault/
│   ├── cli.py               # Typer app: все команды
│   ├── vault.py             # VaultManager — оркестрация crypto + storage
│   ├── crypto.py            # обёртки Argon2id KDF + AES-GCM (тонкие, намеренно)
│   ├── storage.py           # бинарный формат, парсинг заголовка, atomic write, lock, sidecar
│   ├── models.py            # Pydantic v2: VaultEntry / VaultMetadata / KDFConfig
│   ├── generator.py         # генерация паролей через secrets
│   ├── clipboard.py         # копирование + запуск detached-очистителя
│   ├── clipboard_clearer.py # точка входа helper-процесса (очистка по таймеру)
│   ├── password_policy.py   # статический список частых утёкших паролей
│   ├── exceptions.py        # таксономия ошибок (oracle-safe)
│   └── config.py            # пути, протокольные константы, KDF-диапазоны
├── tests/                   # crypto, storage/конкурентность, vault, e2e CLI
├── ARCHITECTURE_ru.md       # дизайн-запись: threat model, спека, история ревью
└── pyproject.toml           # зависимости + консольная точка входа `vault`
```

Направление зависимостей строго вниз: `cli → vault → {crypto, storage, generator,
clipboard} → models`. `crypto.py` и `storage.py` не знают друг о друге.

## Требования

- **Python** 3.12 или новее
- **ОС**: Linux, macOS, Windows. POSIX получает настоящие права `0600` и `flock`; Windows
  использует блокировки `msvcrt` и не имеет поддержки ACL (см.
  [ограничения](#модель-безопасности-и-ограничения))
- На Linux для работы буфера обмена нужен установленный `xclip` или `xsel`
- Не требуются и не предпринимаются: GPU, внешние сервисы, доступ к сети

## Конфигурация

KDF-параметры задаются один раз при `vault init` и хранятся внутри заголовка vault'а; их можно
сменить позже через `vault change-master-password`.

### KDF-параметры (флаги `vault init`)

| Флаг | Дефолт | Диапазон | Описание |
|---|---|---|---|
| `--time-cost N` | `3` | 2..10 | число проходов Argon2id |
| `--memory-cost N` | `65536` | 19456..262144 KiB | memory cost (19..256 MiB); верхняя граница намеренная — враждебный заголовок не должен убивать вас OOM'ом |
| `--parallelism N` | `4` | 1..8 | потоки Argon2id |

Дефолты следуют OWASP Password Storage Cheat Sheet для Argon2id (~0.5–1 с разблокировка на
современном ноутбуке).

### Переменные окружения и пути

| Параметр | Дефолт | Описание |
|---|---|---|
| `SSV_VAULT_PATH` | `~/.secure_vault/vault.enc` | расположение vault'а; каждая команда также принимает `--vault-path` |

Производные файлы лежат рядом с vault'ом: `vault.enc.bak` (бэкап одного поколения),
`vault.enc.rev` (sidecar ревизий), `vault.enc.lock` (lock записи). Секретов в них нет.

## Использование

```
vault init                          # создать новый vault, задать мастер-пароль
vault add <title>                   # добавить запись (секрет вводится скрыто)
vault get <title> [--print]         # скопировать в буфер / вывести на экран
vault list [--tag TAG]              # список записей без секретов
vault update <title>                # изменить запись
vault delete <title>                # удалить запись
vault generate [--length N]         # стойкая генерация пароля (unlock не нужен)
vault change-master-password        # re-encrypt с новым паролем + новый salt
vault status                        # ревизия, путь к бэкапу — без пароля
```

Дубли title резолвятся к последней добавленной записи с видимым предупреждением. Сила пароля
(≥ 12 символов, отсутствие во встроенном списке утёкших) проверяется при `init` /
`change-master-password`; проверка предупреждает, но не блокирует жёстко (явный обход —
`--i-know-its-weak`). Сетевые запросы не выполняются никогда — список утёкших паролей поставляется
внутри пакета.

## Экспорт и импорт

Зашифрованный round-trip для бэкапов и переезда между машинами:

```bash
vault export --out backup.enc        # запросит отдельный пароль для экспорта
vault import backup.enc              # в существующий vault...
vault import backup.enc --init-if-missing   # ...или сразу в свежий
```

Импорт мержит: коллизии UUID пропускаются по умолчанию (запись уже была импортирована), дубли
title импортируются с предупреждением о неоднозначности. `--overwrite-conflicts` переключает
пропуск на перезапись — только явно, никогда по умолчанию.

Есть и намеренный аварийный выход:

```bash
vault export --out secrets.json --unsafe-plaintext-json secrets.json
```

Незашифрованный JSON в файл (никогда не stdout), интерактивное подтверждение на терминале, а на
пайпах/CI — **оба** фактора: `--yes-i-understand` И литеральный `y` на stdin. Обратный импорт этого
JSON намеренно вне скоупа v1. См. [SECURITY_ru.md](SECURITY_ru.md).

## Модель безопасности и ограничения

Полный threat model: [ARCHITECTURE_ru.md](ARCHITECTURE_ru.md) §2. Короткая честная версия.

**Защищаем от:** офлайн-атакующего с файлом на руках (украденный ноутбук, утёкший бэкап);
brute-force слабоватых паролей (memory-hard KDF с верхней границей, чтобы враждебный заголовок не
убил вас OOM'ом); подмены/повреждения/усечения (GCM-тег + заголовок, связанный через AAD);
параллельных писателей, портящих данные (весь цикл под одним lock'ом); случайного отката к старой
копии (sidecar ревизий).

**Явно НЕ защищаем от:** кейлоггеров и malware в момент ввода; дампов памяти во время выполнения
команды; root/administrator на машине; противника, согласованно откатывающего *всю директорию*
(вместе со sidecar); снифферов буфера обмена в ~20-секундном окне; видимости title записей в
`ps`/истории shell.

Платформенные оговорки: права `0600` — no-op на Windows (ACL не выставляется); очиститель буфера
по природе best-effort; каждая команда платит ~0.5–1 c за Argon2id, потому что сессии stateless по
дизайну — ключ живёт в памяти ровно столько, сколько длится одна операция.

## Тестирование

```bash
pytest            # 88 тестов, несколько секунд, без сети, фикстуры только tmp_path
```

Набор нацелен на failure mode, критичные для такого инструмента: bit-flip каждого байта AAD,
уникальность nonce под детерминированным моком, эквивалентность wrong-password и corrupted-
ciphertext как oracle, освобождение lock'а при инжектированных сбоях, конкурентность на lost
update (потоки + барьеры), обработка битого `.rev`, очистка tempfile при фейле запуска процесса,
e2e-сценарии CLI через тест-раннер Typer.

Случайность мокается детерминированно, поэтому ничего не флакает. Соответствие задокументированных
failure mode и регрессионных тестов — в ARCHITECTURE_ru.md §12.

## Дорожная карта

Примерный порядок, не обещания:

- **Опциональный режим разблокированной сессии** (`vault unlock --timeout`) с фоновым процессом,
  держащим производный ключ — отдельная архитектурная поверхность, требующая собственного раунда
  threat model.
- **Полный датасет утёкших паролей** (несколько тысяч записей) вместо встроенного списка на ~100
  записей.
- **Поддержка Windows ACL** для файла vault'а через `pywin32` — снятие главного Windows-оговорки.
- **`vault status --json`** и другие scripting-friendly форматы вывода.

## FAQ

**Почему не просто KeePassXC / Bitwarden?** Пользуйтесь ими — это отличные продукты. Этот проект
существует, чтобы продемонстрировать построение *всего* конверта правильно (формат, атомарность,
блокировки, эргономика CLI, threat modeling) — именно то, что эти инструменты прячут.

**Почему не реализовать AES самому?** Потому что тонкий баг переиспользования nonce проходит все
юнит-тесты, уничтожая гарантию безопасности. Самописная криптография демонстрирует не то. Работа в
этом проекте — вокруг примитивов: атомарная запись, блокировки, детекция rollback, oracle-safe
ошибки.

**Я забыл мастер-пароль. Можно восстановить данные?** Нет. Никаких бэкдоров, ключей восстановления,
«подсказок к паролю». Для менеджера секретов это корректное поведение, но забытый пароль означает
потерянный vault. Бэкап `.bak` одного поколения помогает при повреждении файла, но не при забытом
пароле.

**Буфер обмена действительно безопасен 20 секунд?** Нет — только best-effort. Любой процесс на
машине может читать буфер в любой момент. Автоочистка сужает окно, но не устраняет его. Для
враждебного окружения используйте `--print` с осторожным пайпом или вообще не проводите секрет
через эту машину.

**Он куда-то стучится / проверяет пароли через HIBP?** Никогда. Сетевого кода ноль. Проверка
утёкших паролей идёт по небольшому статическому списку внутри пакета.

**Почему каждая команда занимает ~1 секунду?** Это Argon2id делает свою работу — делает brute-force
дорогим для всех, включая вас. Сессии stateless по дизайну; возможный режим разблокированной
сессии — в дорожной карте.
